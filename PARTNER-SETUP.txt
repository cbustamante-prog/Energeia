ENERGEIA - SETUP GUIDE FOR A DIFFERENT LAPTOP
==============================================

GitHub project:
https://github.com/cbustamante-prog/Energeia

This guide is for Windows and PowerShell. Each developer runs a local copy
of the website and API connected to the project's Supabase PostgreSQL
database. Register your own Energeia account. Do not share database
passwords or .env files.


1. GET ACCESS AND INSTALL TOOLS
-------------------------------

If the GitHub repository is private, ask the owner to add your GitHub
account as a collaborator. Accept the invitation before cloning.

Install these tools before continuing:

- Git for Windows
- Node.js (includes npm)
- Python 3.11 or newer
- uv for Python dependency management:
  https://docs.astral.sh/uv/getting-started/installation/
- A Supabase account with access to the Energeia project

After installing them, open PowerShell.


2. DOWNLOAD THE PROJECT
-----------------------

Do not run `git clone` from `C:\Windows\System32`. That is a protected
Windows folder, so Git cannot create the project there. In PowerShell, run
these commands to clone into a folder under your Windows user profile:

    New-Item -ItemType Directory -Force "$HOME\source" | Out-Null
    Set-Location "$HOME\source"
    git clone https://github.com/cbustamante-prog/Energeia.git
    cd Energeia

This downloads the latest version of the project from the main branch.
If Git reports that you do not have permission, ask the owner to add your
GitHub account to the private repository and accept the invitation.

When the project is already cloned and you want to get later updates,
open PowerShell in the project folder and run:

    git pull origin main


3. PREPARE THE SUPABASE DATABASE
--------------------------------

1. Create or open the Energeia project in Supabase.
2. Open the project's SQL Editor.
3. Open backend/schema.sql from the cloned project, copy the entire file
   into a new SQL Editor query, and run it.

The script creates the PostgreSQL tables and an unconfigured electricity
rate. It does not copy, delete, or change records in an existing MySQL
database. The old backend/migrate.sql file is MySQL-only; do not run it in
Supabase.

In the Supabase dashboard, open Connect and copy the Session pooler
connection string. The database password is available/reset from the
project's database settings. Never commit or share this connection string.

4. START THE FASTAPI BACKEND
----------------------------

Open PowerShell in the project folder and run:

    cd backend
    Copy-Item .env.example .env
    uv sync
    uv run uvicorn app.main:app --reload

Keep this PowerShell window open while using the site. Edit
backend\.env and replace DATABASE_URL with the Supabase Session pooler
connection string. Use the SQLAlchemy driver prefix
"postgresql+psycopg://" instead of "postgresql://", and keep
"?sslmode=require". URL-encode special characters in the password (for
example, write %40 for @). Keep .env private and never put this database
URL in the frontend.

Check that the API and database are connected by opening:

    http://localhost:8000/api/health

The expected response is:

    {"status":"ok","database":"connected"}

Interactive API documentation is available at:

    http://localhost:8000/docs


5. START THE WEBSITE
--------------------

Open a SECOND PowerShell window in the project folder and run:

    cd frontend
    Copy-Item .env.example .env
    npm ci
    npm run dev

Keep this window open too. Open the local URL Vite displays; it is usually:

    http://localhost:5173

Create your own Energeia account on the site. Then create a household,
set the electricity provider and rate from your bill, add appliances, and
add their usage schedules. Estimates appear once at least one appliance
has an active usage schedule; empty periods are not saved as zero-use bills.


6. RUN TESTS (OPTIONAL)
-----------------------

Frontend unit tests and production build:

    cd frontend
    npm run test.unit
    npm run build

Backend API tests (uses an isolated SQLite test database):

    cd backend
    uv run pytest

The backend test suite uses an isolated in-memory SQLite database and does
not require Supabase or change its records.


TROUBLESHOOTING
---------------

- If cloning fails, confirm your GitHub account has access to this
  repository and reopen PowerShell after installing Git.
- If PowerShell says "Copy-Item cannot find path", check that you are in the
  project folder (the command prompt should end in \Energeia\backend or
  \Energeia\frontend, as appropriate).
- If the website says it cannot reach the API, check that the backend
  PowerShell window is still running and that the health URL above works.
- If the health response says the database is disconnected, confirm the
  Supabase project is available and backend\.env has the correct Session
  pooler host, username, password, port, and sslmode.
- If PowerShell says "uv" or "npm" is not recognized after installation,
  close and reopen PowerShell, then try again.
- If port 5173 or 8000 is already in use, stop the other development
  server using that port before starting Energeia.

- "localhost" is this laptop. These steps run the app locally on the laptop;
  they do not publish it on the internet or connect it to another laptop's
  database.
